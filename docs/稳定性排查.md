# 三组桌面测试稳定性排查

日期：2026-10-18。范围：长文气泡悬停展开、划词滚轮交互、复制／剪贴板。使用合成文字和本地模拟服务，不调用真实 API，不记录剪贴板正文或其他窗口标题。

## 1. 划词按钮：确认并修复产品缺陷

鼠标钩子原来把普通滚轮和点击放在同一个“忽略自身进程窗口”的分支里。为了让用户能够点击翻译按钮，自身窗口点击需要保留；但滚轮也被一并忽略。因此鼠标滚到划词按钮或本程序浮层上时，旧按钮可能不消失。

修复前加入定向用例：真实拖选外部合成文本，移动鼠标到划词按钮，确认原生命中该按钮，再发送滚轮。三轮都复现按钮仍在；观察器记录收到滚轮、目标属于测试进程、左键已松开。报告位于本地忽略目录 `work/stability-before`。

修复将普通滚轮从点击过滤中分开处理：拖选期间按住左键滚动仍保留选区手势；松开后的普通滚轮取消待执行的选区探测并隐藏按钮，包括鼠标位于本程序窗口上的情况。点击按钮翻译、保持原文焦点的行为继续保留。

## 2. 复制：失败发生在测试读回

三轮原路径复查中，有一轮再次出现 `CLIPBRD_E_CANT_OPEN`。捕获的栈位于 `IDataObject.GetData → DataObject.OleConverter → Clipboard.GetText → CopyTest.Remember`；当时 `ClipboardWriter.IsBusy` 为 false，按钮已显示复制成功。该失败来自测试验证所用的 OLE 读取路径，未发现后台复制按钮处理发生卡顿或虚报成功。

未能确认外部占用进程。`GetOpenClipboardWindow` 为零不能证明没有占用：调用者以 NULL 窗口打开剪贴板时该 API 也返回零，见 [微软文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getopenclipboardwindow)。

测试读回改为后台 Win32 Unicode 读取，最多等待 800 毫秒，仅在无法取得剪贴板锁时重试。成功取得锁后，内容不匹配、Unicode 数据缺失或超限都会立即失败，不靠重读掩盖错误结果。正式程序的 `ClipboardWriter` 未因此修改。

新增受控用例用独立消息窗口持有剪贴板：确认读者确实先遇到占用，释放锁后验证 Unicode 内容一致，再故意提供错误期望值，确认仍会失败。原有持续占用时正确报失败、释放后重试、复制中关闭气泡、按钮处理耗时检查继续保留。

## 3. 悬停展开：未复现产品冻结，强化测试条件

原记录中高度已由 69 增长到 400，但固定等待 80 毫秒后没有检测到悬停。初次三轮复查全部正常。继续检查时也记录到一次气泡在建立鼠标落点之前已关闭，以及一次悬停前置条件没有成立；不能仅凭这些情况认定产品展开冻结，也不能确定最初那一次悬停失败的具体来源。

测试现在等待原生窗口命中与 WPF 悬停状态同时成立，若气泡已关闭或鼠标未进入，会明确报告前置条件失败。每一批长文到达后继续验证鼠标仍在气泡内，并保留原有至少增长 100 的断言。

## 结果与边界

修复后的三组检查固定执行五轮，逐轮保留结果，不自动丢弃失败轮；报告位于 `work/stability-confirmed`。长文各轮实际高度由 69 增长到 400，所有鼠标采样均确认原生命中和 WPF 悬停。滚轮观察确认事件落在按钮上且左键已松开。复制检查确认真实读锁争用以及错误内容不能误过。

首次修正测试夹具时还出现输入事件未送达即断言、受控读锁未形成预期争用等情况，报告保留在 `work/stability-after`。最终测试改为等待真实鼠标按下／松开及滚轮到达，并用专用窗口持锁；未通过放宽产品断言来取得通过。

五轮三组合计为 75 次用例执行，并不是新增 75 个不同功能。鼠标键盘外部操作、剪贴板管理器、远程桌面和其他全局钩子仍可能干扰桌面测试；不承诺全部机器或环境均已验证。更新前请从托盘退出旧版，已保存的配置和密钥可以沿用。

另补五轮跨进程检查：每轮三个全新 WPF 子进程直接调用 Clipboard.GetText，15 个独立 WPF 读者均取得完整一致的合成 Unicode 内容，无读取异常；此处不使用辅助读回重试，确认后台原生写入可以被其他 WPF 进程读取。
